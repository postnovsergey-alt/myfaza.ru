# Дизайн веб-версии и Mini App

Спецификация для спринта 4. Один код на два канала: сайт (PWA) и Telegram
Mini App. Различается только обёртка навигации и источник темы.

---

## 1. Три ограничения, которые важнее красоты

Прежде чем что-то рисовать — эти три пункта не обсуждаются. Каждый из них
режет решения, которые иначе выглядят соблазнительно.

### 1.1. Дискретность

Приложение открывают в метро, в очереди, за рабочим столом. Иконка висит на
домашнем экране, где её видят все, кто берёт телефон в руки.

**Проверка взглядом через плечо:** посторонний человек, скользнувший глазами
по экрану на полсекунды, не должен понять, о чём приложение.

Отсюда запрет:

- ❌ Розовый как основной цвет фона или крупных плоскостей
- ❌ Капли, цветы, лепестки, женские силуэты, символы Венеры
- ❌ Слова «менструация», «цикл», «месячные» крупным кеглем на главном экране
- ❌ Иллюстрации репродуктивной системы

Женственность в этом продукте создаётся температурой цвета, мягкостью
скруглений, воздухом и типографикой — не розовым фоном. Это не уступка
и не компромисс: сдержанный интерфейс здесь просто лучше решает задачу
пользовательницы.

### 1.2. Бюджет производительности

NFR-3 из ТЗ: бандл **< 250 КБ gzip**, first meaningful paint **< 3 с на 3G**.

Это жёсткий лимит, а не пожелание. Он определяет выбор инструментов
анимации целиком (см. раздел 4). Красивое, но тяжёлое приложение проигрывает
Telegram-боту, который открывается мгновенно, — а бот у нас конкурирует
с сайтом за одну и ту же пользовательницу.

Проверка: `npm run build` печатает размеры. Превысили — режем, а не
оправдываемся.

### 1.3. Тон

Это приложение о здоровье, и открывают его в том числе тревожные люди.
Женщина, отмечающая задержку на десятый день, не хочет конфетти.

- ❌ Конфетти, салюты, «Ура!», празднование любых событий
- ❌ Восклицательные знаки в системных сообщениях
- ❌ Геймификация: серии, стрики, достижения, «вы молодец, отмечали 7 дней подряд»
- ❌ Бодрая мотивация и эмодзи в интерфейсе
- ✅ Спокойная констатация: «День цикла 12», «До менструации 16 дней»

Движение — плавное и затухающее, никогда не пружинящее и не игривое
в моменты ввода данных.

## 2. Палитра и токены

### 2.1. Цвет — «Тёплый песок» (утверждено 26.07.2026)

Тёплая песочная база, глубокий розовый акцент, медовый вторичный.
Женственность создаётся температурой цвета, а не розовым фоном — палитра
проходит проверку взглядом через плечо (см. 1.1).

Значения в OKLCH: перцептивно ровные шаги, производные оттенки считаются
через `color-mix()` и не разъезжаются по светлоте, как это происходит с HSL.

```css
:root {
  --bg:           oklch(95.9% 0.010 82);   /* #F5F1EA  фон страницы */
  --surface:      oklch(100%  0     90);   /* #FFFFFF  карточки */
  --surface-alt:  oklch(93.0% 0.015 81);   /* #EDE7DD  вложенные блоки */

  --text:         oklch(29.2% 0.004 107);  /* #2C2C2A */
  --text-soft:    oklch(48.2% 0.006 95);   /* #5F5E5A */

  --accent:       oklch(48.2% 0.136 3);    /* #993556  действия, менструация */
  --accent-hi:    oklch(55.0% 0.150 4);    /* #B54468  hover */
  --accent-soft:  oklch(85.9% 0.063 357);  /* #F4C0D1  фон-подложка */

  --second:       oklch(62.2% 0.130 67);   /* #BA7517  фертильное окно */
  --second-soft:  oklch(95.3% 0.029 81);   /* #FAEEDA */
  --second-dark:  oklch(48.0% 0.104 64);   /* #854F0B  овуляция */

  --border:       color-mix(in oklch, var(--text) 12%, transparent);
  --border-strong:color-mix(in oklch, var(--text) 22%, transparent);

  --radius-sm: 10px;
  --radius:    14px;
  --radius-lg: 20px;
}

:root[data-theme="dark"] {
  --bg:           oklch(21.1% 0.005 68);   /* #1A1816 */
  --surface:      oklch(25.5% 0.006 56);   /* #252220 */
  --surface-alt:  oklch(29.0% 0.007 56);

  --text:         oklch(94.2% 0.012 80);   /* #F0EBE3 */
  --text-soft:    oklch(71.3% 0.014 71);   /* #A8A199 */

  --accent:       oklch(73.7% 0.116 359);  /* #E58AA8  светлее — контраст на тёмном */
  --accent-hi:    oklch(79.0% 0.110 359);
  --accent-soft:  oklch(31.0% 0.069 353);  /* #4A2033 */

  --second:       oklch(76.7% 0.125 77);   /* #E0A84E */
  --second-soft:  oklch(30.0% 0.050 70);
  --second-dark:  oklch(70.0% 0.110 70);

  --border:       color-mix(in oklch, var(--text) 14%, transparent);
  --border-strong:color-mix(in oklch, var(--text) 26%, transparent);
}
```

Тёмная тема — не инверсия светлой. Акцент в ней осветляется до
`oklch(73.7% ...)`: тот же `#993556` на тёмном фоне даёт контраст ниже 4.5:1
и читается как грязное пятно.

**Фазы цикла — единственное место, где цвет несёт смысл.** Различимы
по светлоте, а не только по тону: это нужно для дальтонизма и для чтения
экрана при ярком солнце.

| Фаза | Оформление | Токен |
|---|---|---|
| Менструация, факт | Сплошная заливка | `--accent` |
| Менструация, прогноз | Пунктирная обводка 1.5px, фон прозрачный | `--accent` |
| Фертильное окно | Заливка 20% | `--second-soft` |
| Овуляция | Точка 5px под числом, без заливки дня | `--second-dark` |
| Сегодня | Кольцо 2px | `--border-strong` |

Прогноз и факт **обязаны** различаться не только цветом — отсюда пунктир.
Пользовательница должна с одного взгляда понимать, где её данные,
а где догадка приложения.

### 2.2. Типографика

Шрифт с полной кириллицей и вариативным начертанием. Кандидаты: **Manrope**
(мягкий, геометричный, отличная кириллица) или **Inter**. Один вариативный
файл, `font-display: swap`, подмножество только кириллица + латиница + цифры.

| Роль | Размер | Вес | Межстрочный |
|---|---|---|---|
| Крупное число (день цикла) | 44px | 500 | 1.1 |
| Заголовок экрана | 20px | 500 | 1.3 |
| Основной текст | 15px | 400 | 1.55 |
| Вторичный | 13px | 400 | 1.5 |
| Подпись | 11px | 400 | 1.4 |

Минимум 11px. Заголовки — `text-wrap: balance`, абзацы — `text-wrap: pretty`.
Регистр предложения везде, никаких ЗАГЛАВНЫХ и Каждого Слова С Большой.

### 2.3. Сетка и касания

- Базовая единица 4px, отступы кратны ей
- Минимальная зона касания **44×44px**
- Главное действие — в нижней трети экрана, в зоне большого пальца
- Контент по горизонтали: 20px отступы, максимум 480px по центру на десктопе

## 3. Язык движения

Анимация здесь не украшение, а объяснение: откуда взялся элемент, куда
он делся, что изменилось.

### 3.1. Длительности и кривые

```css
:root {
  --dur-instant: 120ms;   /* нажатие, ripple, чекбокс */
  --dur-fast:    200ms;   /* появление, скрытие мелких элементов */
  --dur-base:    320ms;   /* переходы экранов, раскрытие карточек */
  --dur-slow:    900ms;   /* заполнение кольца цикла при входе */

  --ease-out:  cubic-bezier(0.22, 1, 0.36, 1);
  --ease-in:   cubic-bezier(0.55, 0, 1, 0.45);
  --ease-soft: linear(0, 0.35 12%, 0.72 26%, 0.92 40%, 1 62%, 1);
}
```

`--ease-soft` — пружина, собранная функцией `linear()` прямо в CSS,
без физического движка и без килобайта JS. Используется там, где нужно
ощущение мягкой инерции: раскрытие листа настроек, возврат свайпа.

**Ничто не анимируется дольше 400 мс**, кроме кольца прогресса при первом
открытии. Интерфейс, который заставляет ждать свою анимацию, воспринимается
медленным, каким бы красивым он ни был.

### 3.2. Что анимируем

| Событие | Движение |
|---|---|
| Переход между экранами | Кросс-фейд + сдвиг 8px по направлению навигации, `--dur-base` |
| Открытие дня в календаре | Раскрытие карточки из ячейки, общий элемент |
| Отметка начала цикла | Кольцо перерисовывается на новое значение, `--dur-slow`, без вспышек |
| Нажатие кнопки | `scale(0.975)`, `--dur-instant`, + haptic в Telegram |
| Появление списка | Стаггер по 30 мс на элемент, максимум 6 элементов, дальше без задержки |
| Смена месяца в календаре | Горизонтальный сдвиг сетки, `--dur-fast` |
| Загрузка данных | Скелетон той же формы, что и контент. Не спиннер |

### 3.3. Что не анимируем

- Числа не «крутятся» при изменении — цифра меняется сразу
- Ничего не анимируется при повторном входе на уже посещённый экран
- Никаких параллаксов, никаких анимаций фона, ничего в бесконечном цикле
- Никакой анимации при появлении ошибки — она должна быть заметна мгновенно

### 3.4. Уважение к настройкам системы

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

Обязательно. Для части людей вестибулярные расстройства делают анимацию
физически неприятной, а «плавные» переходы — источником тошноты.

## 4. Технические приёмы

Приоритет — платформенные возможности. Каждая из перечисленных ниже даёт
эффект, за который раньше платили килобайтами JS, и стоит ноль.

### 4.1. Берём

| Приём | Зачем | Вес |
|---|---|---|
| **View Transitions API** | Переходы между экранами и общие элементы (ячейка календаря → карточка дня) на уровне браузера | 0 |
| **`@starting-style` + `transition-behavior: allow-discrete`** | Анимация появления элементов из `display:none` без JS | 0 |
| **Scroll-driven animations** (`animation-timeline: view()`) | Появление карточек статистики при прокрутке, целиком на GPU | 0 |
| **`linear()` easing** | Пружинные кривые без физического движка | 0 |
| **Container queries** | Компоненты подстраиваются под контейнер, а не под окно — один код для Mini App и широкого сайта | 0 |
| **OKLCH + `color-mix()`** | Производные оттенки считаются в CSS, палитра не разрастается | 0 |
| **`content-visibility: auto`** | Длинные списки истории не тормозят | 0 |

Для нескольких сложных случаев (перетаскивание, жесты) — `motion/mini`
(микро-сборка библиотеки motion, порядка 2–3 КБ). Полный `motion/react`
брать только если без него не обойтись, и обосновать в `DECISIONS.md`.

### 4.2. Не берём

- ❌ **Lottie** — 60+ КБ ради анимаций, которые здесь не нужны
- ❌ **GSAP** — избыточен, CSS покрывает всё, что нам требуется
- ❌ **Полный Framer Motion** без обоснования
- ❌ **Библиотеки компонентов целиком** (MUI, Ant Design) — тянут дизайн-систему,
  которая нам не подходит, и десятки килобайт. Компоненты пишем свои,
  примитивы доступности берём из headless-библиотеки
- ❌ **Иконочные шрифты целиком** — только нужные иконки, инлайн-SVG

### 4.3. Тема в Telegram Mini App

Mini App наследует от Telegram **светлую или тёмную схему** — но не палитру.
Бренд остаётся нашим в обоих случаях. Читаем `themeParams`, определяем
светлую/тёмную, подставляем свой набор токенов. Иначе приложение будет
выглядеть по-разному у пользовательниц с разными темами Telegram, и это
не «адаптивность», а потеря узнаваемости.

## 5. Экраны

Пять штук. Больше в MVP не нужно.

**Главный.** Кольцо с днём цикла и фазой, дата ожидаемой менструации,
одна крупная кнопка действия, недельная полоса дат, нижняя навигация.
Всё остальное — на других экранах. Главный экран решает одну задачу:
за полсекунды ответить «что сейчас» и дать отметить.

**Календарь.** Месяц, разметка по фазам, тап по дню открывает карточку
редактирования. Свайп между месяцами.

**Логирование.** Лист снизу, а не отдельный экран: интенсивность,
симптомы тегами, настроение, заметка. Всё опционально, закрывается свайпом.

**Аналитика.** Три числа (средняя длина, средняя длительность,
регулярность) и столбчатый график последних 12 циклов.

**Личный кабинет.** По разделу FR-8 ТЗ.

### Онбординг

Три вопроса, три экрана, прогресс-точки. Первый прогноз показывается
сразу после третьего ответа — пользовательница должна увидеть ценность
до того, как её попросят о чём-либо ещё.

## 6. Доступность

Не отдельная задача в конце, а условие приёмки каждого экрана.

- Контраст текста ≥ 4.5:1, крупного ≥ 3:1 (WCAG AA)
- Фокус виден всегда, `:focus-visible` с кольцом в 2px
- Вся навигация с клавиатуры, порядок табуляции логичный
- Формы: `<label>` у каждого поля, ошибки связаны через `aria-describedby`
- Динамические изменения — `aria-live="polite"`
- Цвет никогда не единственный носитель смысла (см. 2.1)
- Целевая метрика Lighthouse Accessibility: **> 90**

## 7. MCP-интеграции

Настроены в `.mcp.json` в корне. Агент использует их сам, спрашивать
не нужно.

| MCP | Что даёт | Когда применять |
|---|---|---|
| **chrome-devtools** | Открыть страницу, снять скриншот, прочитать консоль и сеть, замерить производительность | После каждого экрана: посмотреть глазами, что получилось, и починить, не дожидаясь человека |
| **playwright** | Автотесты интерфейса, снимки на разных размерах экрана | E2E-сценарии: онбординг, отметка цикла, подписка на push |
| **figma** | Достать токены, размеры и код из макета | Только если появится макет. Своего дизайнера у проекта нет — не блокироваться на этом |

**Правило замкнутого цикла.** Написал экран → открыл через
`chrome-devtools` → снял скриншот → посмотрел → нашёл несоответствие этой
спецификации → починил → повторил. Не показывай человеку экран, который
сам не видел.

Отдельно замеряй: размер бандла после сборки, Lighthouse Performance
и Accessibility. Цифры — в `PROGRESS.md`.

## 8. Критерии приёмки дизайна

- [ ] Бандл < 250 КБ gzip, проверено выводом сборки
- [ ] Lighthouse Performance > 85, Accessibility > 90 на мобильном профиле
- [ ] Проверка взглядом через плечо пройдена: на скриншоте главного экрана
      посторонний не понимает тему приложения
- [ ] `prefers-reduced-motion` отключает всю анимацию
- [ ] Светлая и тёмная темы, обе проверены скриншотами
- [ ] Одинаково работает в Mini App и в браузере: скриншоты обоих
- [ ] Ни одной анимации дольше 400 мс, кроме кольца при входе
- [ ] Прогноз визуально отличается от факта не только цветом
- [ ] Все зоны касания ≥ 44px
- [ ] Ни одной строки текста в коде вне i18n
