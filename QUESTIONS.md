# Вопросы к человеку

Агент копит вопросы здесь и задаёт их пачкой в конце спринта.
Красная зона (секреты, деньги, продакшен, юридические тексты) — исключение,
там останавливаемся сразу.

Формат: вопрос, почему нужен ответ, что заблокировано, варианты.

---

## Открытые

### 1. Секреты для `.env`

**Нужно:** `BOT_TOKEN` от @BotFather, VAPID-ключи.
`POSTGRES_PASSWORD` уже сгенерирован setup-скриптом.
**Блокирует:** проверку `/auth/telegram` на боевом Telegram (сейчас тесты
работают на фейковом токене); спринт 5 (Web Push).
**Что сделать человеку:** зайти к @BotFather, зарегистрировать
`@moyafaza_bot`, вставить токен в `.env`, строка `BOT_TOKEN=...` —
без trailing-комментария на той же строке (иначе комментарий уходит
в переменную и всё ломается).

### 2. Миграция прод-хостинга в РФ (deadline)

**Нужно:** VPS в РФ (Selectel/Timeweb/RuVDS, 2 CPU / 4 GB / 40 GB диск,
300–600 ₽/мес) и его IP.
**Блокирует:** первый публичный анонс сервиса; регистрацию через
открытые формы; любую рекламу.
**Почему:** сейчас MVP развёрнут в Amsterdam (см. `DECISIONS.md`).
Держать там данные о цикле реальных пользовательниц — нарушение
152-ФЗ ст. 18. Допустимо только для closed-беты «под моим ключом».
**Триггер миграции:** первый пользователь не из круга заказчика,
или любое упоминание сервиса вне личных контактов.

### 4. Uptime-мониторинг: выбор сервиса

**Нужно:** внешний мониторинг `/api/v1/health/ready` с alert-каналом.
**Варианты:**
- Healthchecks.io (dead man's switch, бесплатно): нужно
  зарегистрироваться, создать check для myfaza, прислать ping-URL —
  впишу в /etc/cron.d.
- UptimeRobot (внешний http-monitor, бесплатно 5 монитров): тебе
  зарегаться и добавить URL myfaza.ru/api/v1/health/ready. От меня
  ничего не нужно.
- Внутренний watchdog + алерт через нашего бота: нужен chat_id
  для алертов; минус — при падении всей VPS сообщения не будет.
**Блокирует:** узнаем о падении только когда пойдут жалобы. На
closed-бете 5–10 человек ещё терпимо, дальше — обязательно.

### 5. Астрологический прогноз по знаку зодиака (отложено 2026-07-27)

**Идея (пользователь):** в личном кабинете скромный блок «Прогноз
по знаку зодиака» + селектор из 12 знаков (без даты рождения, без
PII). На HomePage — карточка с ежедневным текстом. Дискретный тон,
без «женского» визуала.

**Не сделано, потому что источник актуальных RU-текстов оказался
сложнее ожидаемого. Проверил три сайта:**
- 1001goroskop.ru — все URL-варианты (`?zn=oven`, `?sign=oven`,
  `/oven/…`) возвращают одну и ту же страницу-виджет; знак
  подгружается через JS.
- horo.mail.ru/prediction/{sign}_today/ — размер HTML **одинаковый
  до байта** для всех знаков (241953). Один шаблон.
- astrostar.ru/goroskopy/na-segodnya/{sign}.html — заголовок в
  HTML есть, тело прогноза снова через JS. Транслитерация
  непредсказуема (`telec.html` → 404).

**Реальные варианты (нужно выбрать):**
- **Claude API + Redis-кэш** (~$0.30–0.50/мес, генерация раз в
  день по 12 знакам, полный контроль тона, дисклеймер о
  недопустимости мед-советов в system-prompt). Требует
  `ANTHROPIC_API_KEY` в `/etc/myfaza/.env`.
- **Playwright/Selenium + парсинг** одного из перечисленных сайтов.
  Тяжело: +250 MB RAM на api-контейнер (VPS 956 MB, тесно),
  +150 MB диска на Chromium, отдельный worker раз в день, борьба
  с антибот-защитой. Юр. риск: тексты не под свободной лицензией
  (ГК РФ ст. 1259). Оценка: 1–2 недели работы + поддержка на всю
  жизнь.
- **Забить** — оставить только лунный календарь (см. п. 6).

**Что сделать человеку:** выбрать вариант.

### 6. Лунный календарь (не начато 2026-07-27)

**Идея:** фазы Луны на CalendarPage. Никакой PII, никаких внешних
API, никакой эзотерики — чистая астрономия. Формула Meeus за 50
строк, точность ±несколько часов на века.

**Стоит ли делать:**
- Плюсы: дёшево (пара часов), не ломает бренд, лунный цикл ≈ 28
  дней — визуальная перекличка с менструальным.
- Минусы: небольшая продуктовая ценность, если пользователю не
  интересна корреляция с Луной. Может быть просто украшением.

**Что сделать человеку:** решить, делаем ли отдельно от астропрогноза.

### 7. Формулировка текста согласия на обработку данных

**Нужно:** утверждённый юридически текст согласия для экрана онбординга.
**Блокирует:** UI-часть согласия в спринте 4 (эндпоинт `/auth/consent`
уже работает, принимает только `version`).
**Что сделать человеку:** согласовать с юристом черновик текста
согласия по 152-ФЗ ст.10 (данные о состоянии здоровья). Указать номер
версии, чтобы `consent_version` было чем заполнить.
